# Incremental clip list sync — October 13, 2026

Windows 1.1.36 preloads the complete archive asynchronously at program startup. Opening Recorded Clips uses that cache and requests changes; it shares an in-progress startup task. Refresh and Review All read /api/v1/clips/sync using the last successfully applied cursor. No-change refreshes avoid list rebuilds. Older controllers fall back to paginated catalog reads.

Controller 1.2.7 keeps a latest-change revision per catalog ID using transactional SQLite triggers. New recordings, updates to old recordings, reviews, deletions, local visibility/validation changes, identity labels/profile names, analysis states and displayed evidence invalidate their affected IDs. Deleted IDs remain as tombstones. A refresh returns only affected visible clip payloads plus removed IDs and current totals. It does not use recording date as a cutoff. Routine catalog_updated_at polling does not invalidate clips.

The response cursor, payload, removals and totals share one read snapshot. Concurrent writes remain available to the next cursor. A failed Windows read/apply keeps the previous cursor. Missing/invalid cursors, controller restarts and changed database epochs request a complete baseline. Tracking tables are additive; recordings, profiles and confirmations are retained. Counts still read SQLite and changed data still runs the normal local filters; this does not eliminate all UI or controller work.

Validation: six incremental-store regressions plus twenty existing catalog/validation/identity/analysis regressions on the staged Pi; WPF startup while Dashboard selected, initial task coalescing, no full reload on navigation, unchanged list-source retention, delta merge/removal, review updates, failed cursor recovery, full reset, legacy fallback, spinner cleanup and About version/date. No production reviews or deletions were performed for tests.

Live verification: the installed Pi returned 15,487 clips / 9,810,301 bytes in 4.167 seconds for a complete baseline, followed by zero changed/removed clips / 203 bytes in 0.054 seconds. These are individual Pi-local HTTP measurements, not guaranteed Windows timings. Both blink-dvr and blink-identity verified active. The first deployment readiness deadline was too short for normal startup recovery and rolled back; the second used a longer readiness window and passed.
