# Camera signal indicators — September 29, 2026

Systems/Devices shows ascending antenna-style Wi-Fi bars and a horizontal segmented Sync Module strength bar on each camera card. Raw values remain visible; tooltips and accessibility text explain the reading. Offline cameras have inactive bars. Missing telemetry says Not reported, which is distinct from a reported zero. Original Mini and Mini 2 cards show Wi-Fi only; the Sync Module indicator is omitted.

The optional `GET /api/v1/devices?signals=true` query enriches the ordinary device response with signal values and their units. Ordinary device-list requests are unchanged. Signal collection uses read-only Blink configuration/status requests when the Systems/Devices view requests details, caches readings for 60 seconds, limits concurrency to three, and bounds each request to three seconds and the batch to eight seconds. Failed telemetry does not fail the camera list. Cancellation drains outstanding work. No setting changes, live streams, or periodic signal polling were added.

Observed sources: Mini/Mini 2 `wifi_rssi`; Outdoor `wifi_strength` and `lfr_strength`; Doorbell homescreen `signals.wifi` and `signals.lfr`. The native Doorbell values are 0–5. Negative values are shown as dBm, with an approximate five-bar display: 5 at -50 dBm or stronger; 4 at -60; 3 at -70; 2 at -80; 1 at -90; below -90 has no filled bars. These display thresholds are our estimates, not a claim to reproduce the official Blink app's thresholds. The original numbers are never converted into an invented percentage.

Blink's official connectivity guide describes camera-to-Wi-Fi and camera-to-Sync-Module indicators: https://support.blinkforhome.com/en_US/fehlerbehebung/wifi-guide. The exact payload fields and numeric scales used here were checked against the installed library and live responses.

Validation: five controller tests passed for native scales/zero, invalid/missing readings, caching and correct camera identity, partial cloud failures, and cancellation cleanup. WPF checks passed JSON numeric parsing, distinct zero/missing display, invalid readings, offline rendering, and PNG rendering; the rendered sample was visually inspected. The Windows Release build passed with zero warnings/errors. An isolated live lookup returned Wi-Fi readings for all 13 cameras, plus Sync Module readings for seven Outdoor cameras and the Doorbell, in 0.788 seconds.


Follow-up: Outdoor and Doorbell cards display Camera Temperature in degrees Fahrenheit. The Doorbell configuration supplies temp (79 F in the initial live inspection); Outdoor configuration supplies temperature. The cached telemetry response includes matching Fahrenheit and Celsius values. A failed Doorbell temperature lookup preserves its available homescreen signal readings. Seven telemetry tests passed, including valid zero temperatures and missing-temperature recovery; the updated Windows Release build passed with zero warnings/errors.

Sync Module follow-up: Wi-Fi indicators now appear beneath module firmware. Blink supplies native 0-5 wifi_strength values in refreshed homescreen sync_modules entries, matched by physical sync_id rather than network_id. If no current entry exists, the module's initialization summary is a fallback; a current entry with no reading stays unavailable. No additional cloud calls are made. Initial values were Home 5/5, Outback 5/5, and Outdoor 3/5. Nine telemetry tests and a clean Windows Release build passed.
